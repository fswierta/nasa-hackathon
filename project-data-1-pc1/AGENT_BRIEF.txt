0. TL;DR (one paragraph)
-------------------------------------------------------------------------------------
Build a WEB-BASED, INTERACTIVE, AI-POWERED ("SI" = "super intelligence") DASHBOARD that
SUMMARIZES, RANKS and INTERPRETS NASA microgravity combustion experiments stored in the
NASA Physical Sciences Informatics (PSI) repository, so that researchers/engineers can quickly
get FIRE SAFETY INSIGHTS for crewed spacecraft, space stations, Moon/Mars bases and pressurized
rovers. The data (24 "Combustion Science" investigations) is already downloaded into ./data
(metadata, experiment parameter tables, file indexes, science documents). Raw data (videos,
images, sensor dumps, ~12.5 TB total) stays on the PSI server; link to it, do not download it.

Official challenge page: https://www.spaceappschallenge.org/2026/challenges/flame-in-freefall/
Full verbatim challenge text: data/reference/challenge_page.txt

2. DOMAIN KNOWLEDGE YOU NEED (physics & context)
-------------------------------------------------------------------------------------
* Microgravity removes BUOYANCY -> no rising hot gases -> no natural convection. Flames become
  spherical, dimmer, often blue, oxygen arrives only by DIFFUSION or by forced airflow
  (ventilation fans). Therefore AIRFLOW SPEED (cm/s) is a key variable in microgravity.
* Fire safety pillars at NASA: PREVENTION (ignition control + material selection based on
  flammability limits), DETECTION (smoke/aerosol sensing), SUPPRESSION (extinguishing agents:
  CO2, He, N2, water mist).
* Material screening standard: NASA-STD-6001 Test 1 (upward flame propagation, done in 1g).
  BASS/Saffire try to bridge 1g screening results and true microgravity flammability.
* Key flammability concepts: flammability limit, Limiting Oxygen Index (LOI) / Maximum Oxygen
  Concentration (MOC), flame spread rate (concurrent vs opposed flow), extinction diameter
  (droplets), burning rate constant K (mm^2/s), smoke point, soot, cool flames (low-temperature
  chemistry, can persist after visible "hot" flame extinction - a hidden hazard).
* Atmosphere numbers (very important for "Moon base" scenario):
    Earth sea level ........ 20.9% O2 @ 14.7 psi (101.3 kPa)
    ISS .................... ~21% O2 @ 14.7 psi
    Spacesuit .............. 100% O2 @ 4.3 psi
    Planned Moon base / pressurized rover: >= 30% O2 @ <= 10.2 psi  (>40% more O2 than Earth
    -> materials much MORE flammable). (Exploration Atmosphere studied by NASA: 34% O2 @ 8.2 psi.)
    Highest-O2 microgravity tests in PSI: ACME CFI-G inverse flames, up to 85% O2.
* Partial gravity (Moon 1/6 g, Mars 3/8 g): NO partial-g combustion data in PSI yet (future:
  LUCI, FM2). ACME E-FIELD Flames mimicked partial-g effects using electric fields on flame ions.
  Strategy suggested by NASA: microgravity (0g) and normal gravity (1g) results BOUND what
  happens at intermediate gravity -> the dashboard can show "bounds" for Moon/Mars.
* Historic incidents to use as motivation/storytelling: Apollo 1 (1967, pure-O2 cabin fire,
  3 crew died), Apollo 13 (1970, O2 tank explosion), Mir (1997, oxygen generator "candle" fire),
  Artemis II (smoke alarm in flight; quote in challenge text).


3. DATA - WHERE IT IS AND HOW TO GET MORE
-------------------------------------------------------------------------------------
3.1 Local folder layout (already downloaded by tools/psi_fetch.py)
  data/
    investigations_catalog.csv / .json  -> 1 row per investigation (24 rows): accession, acronym,
                                         title, projectType, subResearchArea, hardware, platform,
                                         dates, DOI, related IDs, totalSizeGB, nFiles,
                                         fileCategories, experimentalTableRows/Columns,
                                         nPublications, keywords, landingPage
    metadata/PSI-XX.json                -> cleaned metadata: objective, hypothesis, approach,
                                         researchImpacts (Earth benefits), hardware, contacts
                                         (name+affiliation), publications (title, authors, DOI),
                                         license, DOI, dates
    experimental_tables/*.csv           -> 22 CSVs = per-test parameters (the structured data!)
    file_index/PSI-XX_files.csv         -> every file of every investigation: S3 key, name, bytes,
                                         category (Raw Data, Analyzed Data, Science Documents,
                                         Reports, Presentations, Engineering Documents,
                                         Reference Data, Calibration, ...), file id, version
    documents/PSI-XX/*                  -> "Science Documents" + "Reports" (PDF/DOCX, <=40 MB each)
                                         -> use as RAG knowledge base for the AI
    reference/challenge_page.txt        -> verbatim challenge text + resource links
    reference/NASA_Researchers_Guide_ISS_Combustion_Science_2015.pdf  -> 50+ p. overview
  tools/psi_fetch.py                    -> re-runnable fetcher (Python 3, stdlib only)
                                         `python tools/psi_fetch.py`        (metadata+tables)
                                         `python tools/psi_fetch.py --docs` (+ documents)

3.2 PSI web API (unofficial, used by the psi.nasa.gov Angular frontend, NO login needed)
  Base: https://psi.nasa.gov/geode-py/ws
  - List/search:   GET  /repo/search?source=psi&type=investigation&from=0&size=200[&term=...]
                   (Elasticsearch-like JSON; filter _source["Research Area"]=="Combustion Science")
  - Metadata:      GET  /repo/investigations/{PSI-ID}
                   keys: objective, hypothesis, approach, researchImpacts, experimentHardware,
                   doi, publications[], contacts[], experimentalTable[], modelingTable[], readme[],
                   images[], totalFileSize, version ...
  - File tree:     POST /files/v2  JSON body {"folder":"","fileType":"study","studyId":"PSI-ID",
                   "version":<metadata.version>,"obfuscationcode":""}
  - Download:      GET  /studies/{PSI-ID}/download?file={fileId}&version={v}&redirect=false
                   -> returns a short-lived presigned S3 URL (psi-repo-prod.s3.amazonaws.com);
                   then GET that URL. fileId = "_id.$oid" (tables) or "id" (file tree).
  - Thumbnail:     GET  /investigations/{PSI-ID}/image
  - Human landing page: https://psi.nasa.gov/physci/repo/data/investigations/{PSI-ID}
  Be polite: cache results, no parallel hammering, do not bulk-download raw data (TBs).

3.3 License & citation (IMPORTANT for Validity)
  All PSI data here is CC0-1.0. PSI REQUIRES citing each dataset by its DOI (10.60555/...) in any
  presentation/report. The dashboard must show the DOI + link for every investigation it uses,
  and AI answers must cite the PSI-ID/DOI they are based on.

5. DATA QUALITY WARNINGS (handle these in the ETL step)
-------------------------------------------------------------------------------------
* Every experimental table has DIFFERENT columns. Build a per-investigation column mapping into
  a common schema (see 6.1). Do not assume equal headers.
* Units are mixed: pressure in mmHg (FLEX), atm (FLEX-2, Flame Design), bar (CFI-G); O2 as mole
  fraction 0-1 (FLEX, CFI-G XO2) vs percent (SAFFIRE, BRE); flow in cm/s, sometimes with the unit
  inside the cell ("20 cm/s"). Normalize: O2 -> mole fraction, pressure -> kPa, flow -> cm/s.
* Cells may contain ranges/lists ("0.17; 0.21;0.25; 0.3", "1.5 - 5", "~ 21.5", "26.5; 34"),
  free-text notes, typos ("Samle Thickness", "visulation", "037 mm" = 0.37 mm), footnote rows
  ("Note 1 ...") and camera/flow-visualization rows mixed with test rows (SAFFIRE),
  mis-encoded micro sign ("?-g" = "µg"),
  UTF-8 BOM at file start, blank rows, inconsistent spelling ("PMMA 2 cm" / "pmma 2 cm").
* Some tables are test MATRICES (FLEX-2) or day logs (SLICE, ACME CLD/s-Flame/E-FIELD) rather than
  one-row-per-test. Ground studies (PSI-60/62/115/117) have no experimental table.
* Windows: some file names are long -> use a short project path or the \\?\ prefix
  (path > 260 chars fails). PSI-10 table names contain spaces.
* Never invent values. If the AI extracts numbers from PDFs, store the source (file + page).


6. RECOMMENDED SOLUTION DESIGN (you may improve it)
-------------------------------------------------------------------------------------
6.1 Unified knowledge model (build once, offline, store as JSON/SQLite):
  Investigation { id, acronym, title, type(flight/ground), platform, hardware_family,
     fuel_phase (solid|liquid droplet|gas), fuels[], sample_geometry (fabric sheet, rod, sphere,
     droplet D0, burner diameter, nozzle), o2_range, pressure_range_kPa, flow_range_cm_s,
     diluents/suppressants (N2, CO2, He, SF6), measurements/sensors (cameras, radiometers,
     thermocouples, PMT, particle counters, gas analyzers O2/CO2/CO), varied_variables[],
     fixed_variables[], n_tests, key_findings[] (with citation), fire_safety_pillar
     (prevention|detection|suppression|modeling), habitat_relevance {spacecraft, ISS,
     lunar_base, mars_base, rover}, earth_applications[], doi, landing_page, publications[] }
  Test { investigation_id, test_id, date, fuel, material, geometry, o2_frac, pressure_kPa,
     flow_cm_s, diluent, outcome (ignited/extinguished/burned out/disrupted), burn_time_s,
     spread_rate, extinction_diameter_mm, ... raw_row }

6.2 AI ("SI") layer:
  - RAG over: metadata JSON (objective/hypothesis/approach/impacts) + documents/ PDFs + the
    Researcher's Guide PDF. Chunk, embed, retrieve; every answer cites PSI-ID + DOI (+ file/page).
  - LLM-generated per-investigation summary cards (plain-language + expert version), cached.
  - LLM-assisted ETL: extract fuels / conditions / sensors / findings from text into the schema
    above, then HUMAN-CHECK the values shown in the dashboard.
  - Scenario-based RANKING: user describes a habitat scenario (e.g. "lunar rover cabin, 34% O2,
    8.2 psi, ventilation 10 cm/s, Nomex & PMMA materials") -> score each investigation:
       score = w1*overlap(O2 range) + w2*overlap(pressure) + w3*overlap(flow) + w4*material/fuel
               similarity + w5*pillar match + w6*relevance tier (A/B/C) + w7*data richness
     show the score breakdown (explainability!) and let the user tune the weights.
  - "Ask the data" chat: natural-language questions -> answer + citations + linked charts.
  - Optional ML: simple predictive model / regression on FLEX (extinction vs O2, pressure,
    diluent, D0) or BASS/SAFFIRE (spread vs flow, O2) with clear uncertainty; and a "bounds"
    visual for Moon/Mars (0g vs 1g results).

6.3 Dashboard views (suggested):
  1. Overview: 24 investigations as cards/table; filters by fuel phase, pillar, hardware, O2.
  2. Investigation detail: summary, objectives, conditions table, varied vs fixed variables,
     sensors, charts of the test matrix, documents, DOI/citation, link to raw data in PSI.
  3. Compare: 2-4 investigations side by side (conditions, fuels, outcomes).
  4. Scenario ranker: habitat presets (ISS 21%/14.7 psi, Lunar base >=30%/<=10.2 psi,
     Exploration atm 34%/8.2 psi, Mars base, pressurized rover, spacesuit 100%/4.3 psi) ->
     ranked list + "why" explanations + data gaps (e.g. "no partial-g data in PSI").
  5. Condition map: scatter of all tests in O2 vs pressure (and flow) space, colored by
     investigation/outcome, with habitat atmospheres overlaid -> shows coverage & gaps.
  6. Insights: AI-generated cross-investigation insights for prevention / detection /
     suppression, each with citations; "lessons from history" (Apollo 1, Apollo 13, Mir).
  7. Earth benefits: link findings to Spinoffs (water mist, smoke detectors, firefighter gear).

6.4 Suggested stack (keep it simple to finish in a hackathon):
  Frontend: React/Next.js or Streamlit/Dash (fastest). Charts: Plotly / Recharts.
  Backend: Python (FastAPI) + pandas; vector store: Chroma/FAISS/sqlite-vss; LLM via API.
  Precompute summaries & embeddings offline; ship a static JSON so the demo works offline.
  Deploy: Vercel / Streamlit Cloud / Hugging Face Spaces. Put the repo on GitHub.
